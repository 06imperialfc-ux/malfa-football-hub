Public build: node scripts/build.cjs

DATABASE ROLES AND SECURITY
super_admin: full system access; manages administrator roles and scopes.
league_admin: manages assigned competitions, fixtures, standings and related news.
club_admin: manages assigned clubs and related news.

Database RLS is the security boundary. Hidden dashboard tabs only affect usability. The database functions grant_admin_access(email, role, competition_ids, club_ids) and list_admin_access() handle role assignment and directory listing. The target user must first exist in Supabase Auth.

Public policies expose active visible competitions and clubs; fixtures and standings for visible competitions; published news; active partners; and safe settings. Private records require the appropriate scope. The league-media bucket accepts PNG/JPEG/WebP images up to 5 MB. New files use uploader user-ID folders. Content changes are recorded in content_audit_log for superadmin review.

Keep public sign-up disabled. Never put a service-role key in browser code. Create Auth accounts before granting roles. Keep two trusted superadmins before removing the temporary account. Do not rerun supabase-schema.sql on the secured production database.

CONTENT WORKFLOW

Ranking is points, goal difference, goals scored, wins, then club name. A win is 3 points, a draw 1 point, plus any administrator-entered adjustment.

TROUBLESHOOTING
If public data is missing, check the Supabase URL and publishable key in js/cms-config.js, RLS and browser errors. Public pages stop waiting quickly and show an unavailable message if the database cannot be reached.
If admin login fails, check the separate admin deployment, Supabase Auth redirect URLs, Supabase SDK loading and an active admin_users row.
If an admin sees no records, check admin_competitions or admin_clubs assignments, season values, active/visible flags and RLS.
If standings are wrong, check that fixtures are finished, verified, in the current season and have integer scores; then rebuild.
